Launch safety

What someone who may launch a template, but not change it, can make the job do. The defaults keep a launcher to the template's own playbook.

Variables named ansible_* at launch

In extra variables, survey answers, schedules and ad hoc commands. Variables on templates, inventories and hosts are not affected.

Allowed lets a launcher change how Ansible connects and escalates, for example ansible_ssh_common_args or ansible_become_exe, and so run other commands than the playbook's.
Launch fields the template does not prompt for

A limit, an inventory, extra variables… sent at launch when the template does not ask for them.

Ignored: the job starts without them, and the response lists them in ignored_fields. For clients written for AWX that send every field.
Jinja in extra variables

Whether {{ … }} in extra variables is evaluated by Ansible.

A launcher's Jinja runs where the playbook runs, and its lookups can read files and run commands there.

Projects from the server's own files

Git projects with a file:// URL or a local path.

Allowed lets anyone who may create a project check out any directory the server can read. Only for single-tenant installs you trust.
Symbolic links in projects

When awxnext lists a project's playbooks and inventory files.

Followed anywhere lets a project link to files elsewhere on the server and have them listed.
